## 1. Per-dimension scores

**D1 Functionality — 6.** What was actually exercised works: book create 201 (`api-traces\01-book-create.json`), 12-chapter seed, batch create→6/6 completed with internally consistent digest (`04-batch-precancel-status.json`: `childCount`=`completedCount`=6, counts object matches), and 19/21 genuinely-evidenced billing lifecycle checks in w6 (webhook signature, dedup replay, dunning flip/recover, period-end cancel semantics). But a *basic* flow raw-500s (`POST .../chapters` on chapter-1 collision, D-18 cross-ref, worked around via `01c-ch1-content-fix.json`), checkout-while-active is unguarded (DUP-01), and the persona journey itself completed only Day-0 + one Core step before HALT — Power/Edge/Return/Tier/X2 are all unexecuted.

**D2 Reliability & data safety — 5.5.** Strong: webhook replay is provably idempotent with byte-identical DB rows (`_results.json` REPLAY-01), cancel flags are durable (Z10 NOT-REAL), no data lost in any trace. Weak: D-06 (S1) — `POST /billing/checkout` happily creates a second concurrent Stripe subscription for an already-active subscriber (200 + live checkout URL in `w6-lifecycle-steps.json` DUP-01), a direct double-billing risk; Z8 REAL — crash mid-orchestrator re-spends the writer's BYOK money with the ledger under-reporting it; D-17 — the morning notification renders `$0.00` on a Redis hiccup while real spend sits one query away (RED test: `expected '2/2 passes · $0.00 / $10.00 cap' to contain '$6.00'`). Failure states are not consistently honest.

**D3 Usability — 5.** This lens's core, and the evidence cuts both ways. Good: the batch status endpoint is a genuinely strong visibility surface (queued/running/completed/failed/skipped counts, spend vs cap, `haltReason`, per-chapter findings); the post-cancel 403 is plain-language and actionable ("Your subscription is inactive. Subscribe…" + `upgradeToTier`); `statusAutoAdvanceSuppressed:true` respects the writer's control of her own pipeline state. Bad, and heavy: D-07 (S2) — `past_due` and pending-cancellation render **zero** visible difference on the billing page (the code's own `"but warn"` comment is unimplemented), so a writer whose card just failed sees a perfectly healthy screen; D-17 — the one notification a batch user actually reads can state a confident false number; chapter-create failure is a generic `{"error":"Failed to create chapter"}` 500 with no recovery guidance. Billing/spend clarity — which counts under this lens — fails exactly where it matters.

**D3b Ergonomy & efficiency — 4.5.** No direct click-path traces exist, but what's inferable is bad: the billing page's "Upgrade" button on non-current plan cards is wired straight into the unguarded checkout route (D-06 writeup) — the *natural* click path leads to a second subscription, a textbook foot-gun. The competitive teardown (codebase-grounded, in-bundle) documents broken chapter reorder (corkboard→404, canvas→P2002), no find & replace anywhere, word targets rendered in 4 places and settable in 0, and an unwired entity-mention popup — dead-ends for exactly Priya's high-volume revision workflow. No positive ergonomics evidence anywhere in the bundle.

**D4 Onboarding / time-to-first-word — 4 (low confidence, teardown-derived).** No fresh-user evidence exists — Priya is a pre-seeded persona driven via e2e headers; time-to-first-word was never measured. The only onboarding evidence is the teardown: BYOK is mandatory with no managed/no-key tier (ranked gap #4, "BYOK is a moat for pros, a wall for beginners"), no templates/beat-sheets (#8), and the synthesis's own conclusion that "a debut author or hobbyist bounces in the first hour."

Correctly voided; nothing usable remains.

**D6 Look & feel — 4.5 (thin, code-derived).** No screenshots, themes, contrast, or locale testing in the bundle. The only state-design evidence is negative: the billing page renders exactly two conditional banners (`!stripeConfigured`, `isTrialing`) and none for the two states that most need one (D-07); error bodies are raw generic JSON. Teardown's "14 UI languages (7 full)" is the lone locale datum, unexercised.

**D7 Trust & safety — 5.5.** Evidenced holds: signature verification fails closed without leaking internals (SIG-01/02), portal failure leaks nothing (PORTAL-01), post-cancel gate enforces 403 (CANCEL-04), key listing masks the key (`sk-or-v...705e`), persona isolation byte-verified (ISOLATION-01), past_due grace is deliberate and humane. Holes: D-06 (S1) is a billing-trust breach waiting on one click; D-07 hides billing danger states; Z8 spends the user's own key twice on a crash; and the teardown documents live model-identity dishonesty (Coach force-run on Sonnet regardless of the user's model pick; AuthorshipTracker hardcoded "100% human") — for a BYOK product whose stated moat is honest economics, that is a direct wound.

She would trial the batch moat; she would not yet move her business off Scrivener/Novelcrafter, and the price-to-polish ratio is upside-down.

## 3. "Suspiciously clean" analysis

This bundle is not suspiciously clean — it is suspiciously **thin and suspiciously narrated**. Thin: Priya's journey halted after Day-0 plus a single 6-chapter batch on a 673-word toy manuscript; every hard drill her persona exists to run (cap breach, circuit breaker, worker-kill recovery, duplicate submission, 24-child overnight, live morning digest, tier probe) is unexecuted, so the money gates this panel is nominally about are almost entirely untested live — the only failure-path evidence anywhere is one RED unit test and one worked-around 500. Narrated: the single place where raw data shows a FAIL (PRORATE-01/03), the prose upgrades it to PASS via an uncaptured "re-run." Missing evidence I would expect for an EXPERIENCE lens and did not find: any screenshot or browser trace at all (the entire "experience" here is inferred from API JSON and code-read defect reports), any fresh-user onboarding run, any mid-run batch state as a user would watch it, and the actual morning-notification rendering. The healthy-path digest being perfectly self-consistent is believable precisely because the same executor documented where its failure path lies.

## 4. One-line overall impression

A product with a real, unmatched overnight-batch + honest-spend moat whose experience surfaces betray it at the worst moments — billing danger states invisible, the morning digest's notification able to lie, a one-click double-billing foot-gun — graded here on a journey that was only ~20% run and one billing suite whose sole failed assertion was narrated into a pass.
