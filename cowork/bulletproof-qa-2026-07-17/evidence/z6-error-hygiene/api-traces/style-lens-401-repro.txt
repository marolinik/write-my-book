Root cause: src/app/api/books/[id]/style/route.ts POST catch block (~lines 87-91)
and src/app/api/books/[id]/style/lenses/route.ts POST catch block (~lines 71-81)
check invalidJsonBodyResponse and Prisma P2002, then fall through to a generic
`catch { return NextResponse.json({error:"Unauthorized"}, {status:401}) }` for
any other error -- including a Prisma validation error thrown when a String
field receives a non-string value. The bare `catch { return 401 }` shape is
structurally identical in style/route.ts GET, style/lenses/route.ts GET, and
style/lenses/[lensId]/route.ts DELETE, though this sweep only had a body-payload
vector on the two POST handlers above.
