## NEW defects

### D-195 [S3] — Tailwind v4 migration left `hsl(var(--token))` over oklch tokens; all chart colour is invalid CSS
**26 occurrences across 24 lines in 3 files** (`grep -rn "hsl(var(--" src/`):
- `src/components/book/daily-word-chart.tsx` — 2 (`--primary` bar fill, `--muted / 0.3` cursor)
- `src/components/reports/analytics-tab.tsx` — 21 (`--primary`, `--card`, `--border`, `--muted-foreground`
  across every tooltip/axis/series on the reports analytics tab)
- `src/components/ui/sidebar.tsx` — 1 (`--sidebar-accent` in an arbitrary class)

**Root cause.** The design tokens are oklch (`src/app/globals.css:60` `--primary: oklch(0.205 0 0)` light,
`:94` `--primary: oklch(0.922 0 0)` dark). Wrapping them in `hsl()` yields `hsl(oklch(0.205 0 0))`,
which is invalid, so SVG `fill` falls back to its initial value: **black**.

**Why it survived.** In light mode the intended `--primary` is *already* near-black (0.205), so the
black fallback looks approximately correct. In dark mode the intended value inverts to near-white
(0.922) and still renders black — so the bug is only visible in the theme nobody screenshotted.

**Live proof.** 47f/47g: `fillAttr "hsl(var(--primary))"` -> `fillComputed "rgb(0, 0, 0)"`,
identical in `barsLight` and `barsDark`. `47g3-chart-dark-mode.png` shows pure-black bars on the
near-black dark panel — Maya's streak/word-count chart is effectively invisible in dark mode.

**Fix.** Replace `hsl(var(--x))` with `var(--x)` (tokens are already complete colour values). For the
alpha case use `color-mix(in oklab, var(--muted) 30%, transparent)` rather than `/ 0.3`.
Mechanical, 3 files. Add a lint/copy-scan test asserting no `hsl(var(--` remains, matching the
D-182 copy-scan precedent.

### D-197 [S4] — D-139 4th recurrence: FAB clearance protects only the last row at rest

reservation on the Action column at this breakpoint.
